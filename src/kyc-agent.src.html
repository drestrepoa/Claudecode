Architecture view — the reference system

The same agents drawn as the eleven-agent reference architecture: orchestrator, workflow agents A–G, overarching agents X, Y, Z, skills and data underneath.

Modelled on the eleven-agent KYC reference system described by BCG and Anthropic: one orchestrator, seven workflow agents (A–G), three overarching agents (X, Y, Z), each a separate model call with its own small set of deterministic skills. The orchestrator never rates, approves or declines; the rulebook engine rates, a person decides. Consequential actions (a message to the customer, a disposition of a screening hit, an approval, a decline, a referral) pass a gate whose level you set in block 2: the agent acts on its own, acts and notifies, waits for a decision, or is forbidden. Hard limits (a true sanctions match, a High rating without EDD, a sign-off without QA) are code, not settings.

Building blocks — edit me

Three things participants change. Edit, then ask the agent again and watch the trace and the audit log. The orchestrator's instructions are on its box in the diagram above.

1 · Rulebook

deterministic

The rating engine and the thresholds. Cheap, instant, repeatable, and the same for every case. The agent can read it, not change it. Lists are illustrative, not a regulator's.

3 · Agents and skills

agentsdeterministic

Ten agents the orchestrator can delegate to, then the deterministic skills they use. Untick an agent and the orchestrator gets its skills directly; untick a skill and whoever needs it has to work around it. Letters follow the reference architecture.

2 · Governance

humancode

Decision rights. For each consequential action: who decides and how much the agent may do alone. Enforced inside the tools, so the agent cannot talk its way past a gate, and neither can a document.
